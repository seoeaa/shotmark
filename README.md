# Shotmark

<img src="assets/icons/hicolor/256x256/apps/io.github.shotmark.Shotmark.png" width="128" height="128" alt="Shotmark icon">

[![Build](https://github.com/seoeaa/shotmark/actions/workflows/build.yml/badge.svg)](https://github.com/seoeaa/shotmark/actions/workflows/build.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

Аннотатор скриншотов для Linux на Wayland: выделение области, стрелки, фигуры,
текст, PNG и системный трей. **Ранний прототип**, основной целевой дистрибутив — Ubuntu 24.04.

## Готовый пакет Ubuntu / Debian

Скачайте `.deb` и `SHA256SUMS` из [GitHub Releases](https://github.com/seoeaa/shotmark/releases).
В папке загрузки:

```bash
sha256sum --check SHA256SUMS
sudo apt install ./shotmark_0.3.0_all.deb
shotmark --tray
```

`apt` установит системные GTK/Cairo/Ayatana-зависимости. Python-код в пакете
не привязан к CPU-архитектуре (`Architecture: all`), но проверяемая платформа CI —
Ubuntu 24.04 amd64. На других дистрибутивах требуется GTK ≥ 4.10 и соответствующие
пакеты зависимостей; совместимость не гарантируется. В GNOME для значка нужно
включённое расширение AppIndicators. Автозапуск и глобальные горячие клавиши
пакет не добавляет. Удаление: `sudo apt remove shotmark`.

Если ранее установлена пользовательская копия, `~/.local/bin/shotmark` может
перекрывать `/usr/bin/shotmark`. Удалите только эту копию через
`python3 install_user.py --uninstall`, либо явно запускайте `/usr/bin/shotmark`.

## Автоматическая сборка и выпуск

- Каждый push в `main`, pull request и ручной запуск Actions проверяют тесты,
  собирают `.deb`, устанавливают его на runner и выполняют synthetic selftest.
- Пакет и контрольная сумма доступны в **Actions → запуск → Artifacts → shotmark-deb**.
- Push тега `vX.Y.Z`, совпадающего с `app_info.VERSION`, автоматически создаёт
  **GitHub prerelease** с `.deb` и `SHA256SUMS`, только после успешной проверки.
- Никаких персональных CI-секретов не нужно: используется стандартный `GITHUB_TOKEN`.
  Право записи предоставлено только заданию публикации тегированного релиза.
- Иконки уже в исходниках; сборка не вызывает AI API и не требует ключей.

Локальная сборка без sudo:

```bash
/usr/bin/python3 packaging/build_deb.py
# dist/shotmark_0.3.0_all.deb и dist/SHA256SUMS
```

Для нового релиза измените `VERSION` в `app_info.py`, обновите changelog, отправьте
коммит в `main`, затем `git tag vX.Y.Z && git push origin vX.Y.Z`.
Пакет включает только разрешённый список файлов — без `.deps`, локальных резервных
копий и пользовательских изображений. С одинаковым `SOURCE_DATE_EPOCH` сборка
воспроизводима побайтово; это проверяется тестом.

## Зачем

Shotmark запрашивает снимок через `xdg-desktop-portal`. Доступность
выбора области/окна и диалоги разрешений зависят от установленного backend.
`--interactive` запрашивает системный интерфейс, но не гарантирует конкретный
вид диалога. Обычный сценарий:

1. портал отдаёт снимок всего экрана;
2. Shotmark открывает полноэкранное окно с этим снимком;
3. вы выделяете область и рисуете прямо поверх неё;
4. результат копируется в буфер (Ctrl+C) или сохраняется в файл (Ctrl+S).

## Запуск

```bash
python3 shotmark.py                # снять экран и открыть редактор
python3 shotmark.py --interactive  # доверить выбор области самому GNOME
python3 shotmark.py -f shot.png    # аннотировать готовый файл
python3 shotmark.py --capture-only out.png   # только снять экран
python3 shotmark.py --selftest out.png       # искусственный образец, без захвата экрана
```

## Альтернатива: установка из исходников без sudo (0.3.0)

```bash
cd ~/GITHUB/shotmark
/usr/bin/python3 install_user.py
~/.local/bin/shotmark --tray       # открыть значок Shotmark в трее
~/.local/bin/shotmark              # сразу сделать скриншот
~/.local/bin/shotmark --tray --check
~/.local/bin/shotmark --quit-tray  # убрать значок, не закрывая редактор
```

В меню приложений появляется **Shotmark**; обычный запуск открывает трей.
Пункты значка: снимок, системный выбор области/окна, открытие PNG, справка, выход.
Повторный запуск не создаёт второй значок. Пока редактор открыт, захват и выбор
файла из трея временно недоступны — закройте редактор после вставки/сохранения.

Трей работает в отдельном процессе GTK3 с `AyatanaAppIndicator3`, редактор —
в GTK4. Эти версии GTK не загружаются в один процесс. На этой машине зависимости
уже были установлены; на другой Ubuntu могут понадобиться
`gir1.2-gtk-3.0 gir1.2-ayatanaappindicator3-0.1 gnome-shell-extension-appindicator`.
В GNOME должно быть включено расширение AppIndicators.

Установщик копирует приложение в `~/.local/share/shotmark`, создаёт launcher
`~/.local/bin/shotmark` и desktop entry
`~/.local/share/applications/io.github.shotmark.Shotmark.desktop`.
Установленная копия не зависит от текущей рабочей директории. **Автозапуск при входе
не добавляется**, Flameshot и его горячие клавиши не меняются. После изменения кода
повторите установку и перезапустите трей; предыдущая версия сохраняется рядом
в `shotmark-backup-<дата>`. Посторонние файлы/символические ссылки не заменяются.

Удалить установленную копию (исходники, скриншоты и заметки останутся):

```bash
/usr/bin/python3 ~/GITHUB/shotmark/install_user.py --uninstall
```

Из исходников трей запускается отдельно: `/usr/bin/python3 tray.py`.

## Зависимости

Проверяемое окружение: Ubuntu 24.04, системный `/usr/bin/python3` (3.12),
GTK 4.14, PyGObject 3.48. Наличие зависимостей в любой установке Ubuntu
не гарантируется. Полный набор:

```bash
sudo apt install python3-gi python3-cairo python3-gi-cairo \
  gir1.2-gtk-4.0 gir1.2-gtk-3.0 gir1.2-ayatanaappindicator3-0.1 \
  xdg-desktop-portal
```

Для захвата нужны сессионная D-Bus-шина, `xdg-desktop-portal` и backend
вашего рабочего окружения. Для открытия PNG достаточно GTK.

Если прав root нет, соберите локальную копию рядом с проектом:

```bash
./bootstrap-deps.sh    # создаст .deps/, root не требуется
```

`bootstrap-deps.sh` — запасной путь для Debian/Ubuntu: скачивает мост той же
версии, что установленный `python3-gi`, проверяет временную сборку и сохраняет
предыдущую в `.review-backups`. Остальные зависимости уже должны быть установлены.
`cairo_bootstrap.py` не заменяет системный gi: подгружает только недостающий мост,
проверяя совпадение бинарного ядра. После обновления системы устаревшая копия
будет отклонена; пересоберите её. `.deps` и резервные копии исключены из git.

## Горячие клавиши

| Клавиши | Действие |
|---|---|
| `Enter` / `Ctrl+C` | копировать PNG в буфер, оставить редактор открытым |
| `Ctrl+S` | сохранить в `~/Изображения/Screenshot_<дата>.png` |
| `Ctrl+Z` | отменить последнюю аннотацию |
| `Esc` | закрыть без сохранения (или отменить ввод текста) |

После копирования переключитесь через **Alt+Tab** и вставьте изображение.
Не закрывайте редактор до вставки: без менеджера буфера данные принадлежат
процессу приложения. Сохранение тоже оставляет окно открытым для продолжения
работы. Во время ввода текста Enter подтверждает надпись, Ctrl+C/Z принадлежат
полю ввода. Ошибки экспорта показываются в панели, аннотации сохраняются.

PNG публикуется атомарно, без перезаписи файлов. Повторное сохранение добавляет
суффиксы `-1`, `-2` и т. д. `--capture-only` и `--selftest` отказываются заменять
существующий путь. Исходник портала не перемещается и не удаляется.

## Инструменты

Область, стрелка, рамка, эллипс, перо, маркер, текст, мозаика, цифра.
Цвет — шесть пресетов, толщина — ползунок 1–20.

## Устройство

| Файл | Ответственность |
|---|---|
| `portal.py` | захват экрана через `org.freedesktop.portal.Screenshot` (sync и async) |
| `editor.py` | полноэкранный редактор: модель аннотаций и отрисовка на Cairo |
| `shotmark.py` | CLI, жизненный цикл GTK, режим самопроверки |
| `storage.py` | атомарная публикация PNG и копирование снимков без перезаписи |
| `cairo_bootstrap.py` | проверенная локальная поддержка Cairo |
| `tests/` | регрессии на искусственных PNG и fake-портале |

Все координаты аннотаций хранятся в пикселях исходного изображения, а не в
координатах окна, — поэтому результат не зависит от масштаба экрана (HiDPI)
и от того, как картинка вписалась в окно.

## Известные ограничения прототипа

- Полноэкранный режим запрашивается на одном мониторе. Полученный снимок
  вписывается целиком; вид снимка и его расположение на диске определяет портал.
- Поддерживается открытие PNG. Маленькие экраны, разные масштабы мониторов
  и другие оконные менеджеры требуют дополнительной ручной проверки.
- Мозаика не гарантирует необратимого удаления чувствительной информации.
- Нет перемещения и удаления отдельных аннотаций, нет стрелок «от руки»
  кривыми Безье, нет экспорта в JPEG.
- Разрешения на захват определяет система; приложение не меняет их автоматически.

## Проверки

Дополнительно к зависимостям приложения для тестов:
`sudo apt install xvfb xauth dbus desktop-file-utils python3-pil`.

```bash
dbus-run-session --config-file tests/dbus.conf -- xvfb-run -a \
  env -u WAYLAND_DISPLAY GDK_BACKEND=x11 GSK_RENDERER=cairo GTK_A11Y=none \
  /usr/bin/python3 -m unittest discover -s tests -v
/usr/bin/python3 -m py_compile *.py tests/*.py
bash -n bootstrap-deps.sh
```

Тесты проверяют таймаут/отмену/ошибки fake-портала, выделение, стрелки,
сохранение без перезаписи, жизненный цикл приложения и **чтение PNG из буфера
другим процессом**. Окна открываются только в Xvfb; конфигурация тестовой D-Bus
не запускает системные сервисы рабочего стола. `--selftest` не показывает окно,
но требует дисплей GTK (подходит Xvfb).

Это не полная проверка GNOME Wayland: реальные диалоги разрешений, оконный
менеджер и вставка в конкретные Wayland-приложения требуют отдельного прогона.
